# Steam-Authenticated Game Store & Payment Platform — Engineering Case Study

> **OSYSTIC ENGINEERING CASE STUDY · PUBLIC SHOWCASE · SANITIZED · PORTFOLIO-SAFE**

## Problem & constraints

Build a web application that connects external gaming identity with player-specific store state, virtual balances, item management and card-payment checkout while keeping privileged payment operations on the server.

## Architecture & decisions

The private delivery uses Django with Steam OpenID identity, Django ORM persistence and Stripe Checkout/webhook integration. The application models player profiles, virtual coin packages, transactions, game items and player slots.

## Contribution & delivery

The source evidences authenticated player workflows, virtual-balance management, item selection, administrative management, Stripe checkout creation and webhook processing.

## Evidence & outcomes

The retained implementation demonstrates integration of external identity, server-side payment boundaries and domain-specific player/store state. No claim of transaction volume, revenue impact, PCI certification or production uptime is made.

## Confidentiality

Client identity, private source, Steam IDs, Stripe identifiers/secrets, production database content and private operational details remain excluded.


## Public vs. private repository boundary

This repository contains **sanitized public proof only**. The confidential delivery/source repository remains private. Implementation source, Steam/user identifiers, Stripe identifiers/secrets, production database content, client identity, private infrastructure, and protected evidence are intentionally excluded.
